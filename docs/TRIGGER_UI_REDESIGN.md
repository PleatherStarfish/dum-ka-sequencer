# Triggered Tracks — UI redesign (understandability)

The A–F build was correct ("nothing lies") but read as a dense *control panel*:
six bands of terse selects (Beat / Beat idx / Match / Op / Boost % / Snap / 1/N /
Dir …), the two-decision model invisible, and no statement of what a configured
trigger actually does. This redesign keeps the engine, plumbing, and the
"nothing lies" guarantee untouched and rebuilds the **presentation** around
*intent over capability*.

## What changed (UI only — no engine/transport/bridge/patchIo change)

1. **Live plain-language summary** leads the panel — e.g. *"When Lead rests on
   beat 3, play one cycle starting at the trigger. Restart if it fires again."*
   Generated by pure `describeTrigger(config, sourceName)` from the **normalized**
   config the engine compiles, so it can never drift. (`triggerUi.ts`, unit-tested.)
2. **Simple / Advanced disclosure** (`track-trigger-detail`). Simple shows the
   80% path (one condition, placement, length); Advanced reveals the GATE,
   weighted START, quantize, condition trees (Match/NOT/add/any-beat),
   re-trigger, and the roadmap. The summary makes hiding controls safe — it still
   states the full effect (e.g. a preset's gate shows up as "60% of the time").
3. **Two-decision grouping**: bands are wrapped in **Trigger** (*when it fires* —
   WHEN + GATE) and **Play** (*what happens then* — START + RUN), plus an
   **Activity** group (TIMELINE + LOG) during playback. Band headers are verbs:
   *Fire when… · Only… · Start the phrase… · Run for…*.
4. **Humanized trust surface.** The LOG reads "cycle 14, beat 3: answered ·
   started rest center" / "skipped (chance)" via pure `describeDecisionLine`; the
   TIMELINE gains a legend. Both still render the engine trace verbatim.
5. **Reframed entry point + help.** "Mode: continuous/triggered" → "This track:
   plays on its own / responds to a track"; a **?** popover states the
   two-decision model in two sentences.
6. **Consolidated roadmap.** Deferred-but-visible options remain disabled; the
   "Coming later" note sits under Advanced so the day-to-day path has no
   dead-ends.

## Architecture (unchanged discipline)

- All new logic is **pure, React-free helpers** in `triggerUi.ts`
  (`describeTrigger`, `describeWhen/Gate/Start/Run`, `describeConditionNode`,
  `describeDecisionLine`, `describeStartKind`) + the existing `timelineModel.ts`
  selectors — each unit-tested. `TriggerInspector.tsx` is presentation only.
- The component's **props are unchanged**, so `App.tsx` is untouched.
- Every enabled control still maps 1:1 to a real engine capability; deferred
  capabilities stay disabled; the summary/log are generated from the same
  normalized config/trace, preserving timeline==MIDI parity.

## Deferred from the proposal (follow-ups)

- **Full token sentence-builder for WHEN** (P1d): the WHEN row is relabeled and
  reads more naturally ("{source} [is a rest] at beat [3]"), but the fully
  inline Mad-Libs token editor is left as a follow-up; the existing model
  (`whenSpecToEditor`/`editorToWhenSpec`) already backs it when desired.
- **Main-timeline overlay lane** (still a per-cycle strip in the inspector, per
  the Phase E scope note).
